# Competitive observations

Observed **2026-10-24** from upstream READMEs and the PyPI project description.
These are documentation observations, **not independently executed benchmarks**,
security endorsements or proof of missing features. Upstream main branches change;
recheck them before making public comparative claims.

| Project / sources read                                                                                                                                                          | Documented capabilities observed                                                                                                                                                                                                                                                                      | Implication for this project                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [Official conformance](https://github.com/modelcontextprotocol/conformance), [README](https://github.com/modelcontextprotocol/conformance/blob/main/README.md)                  | Client/server protocol scenarios, recorded wire validation, revision-specific requirement sets including 2026-07-28, CI gates and explicit expected-failure baselines.                                                                                                                                | Application-specific value assertions are a different emphasis; do not replace the official protocol suite or claim equivalent conformance coverage.                                                                                                                                                   |
| [MCP Inspector](https://github.com/modelcontextprotocol/inspector), [README](https://github.com/modelcontextprotocol/inspector/blob/main/README.md)                             | Web, CLI and TUI clients plus experimental mcpdo; documented shell/CI connect-list-call-assert workflow.                                                                                                                                                                                              | Automation and headless operation already exist. Repeatable fixture contracts must demonstrate value beyond interactive inspection or a basic CLI.                                                                                                                                                     |
| [mcpward](https://github.com/TsvetanG2/mcpward), [README](https://github.com/TsvetanG2/mcpward/blob/main/README.md)                                                             | Schema/description/annotation drift, CI severity policy, poisoning heuristics, declarative behavioral suites with JSONPath, output-schema and golden checks, latency budgets, JUnit/SARIF/JSON. Some optional checks automatically call tools based on readOnlyHint plus other restrictions.          | Strong overlap: do not describe it as schema-drift-only or claim behavioral testing is novel. ContractLab proposes explicit cases **and** allowlists for every call, never annotation-derived permission. JSON Pointer semantics and diagnostics must be demonstrated before claiming differentiation. |
| [MCPLint](https://pypi.org/project/mcplint-cli/), [PyPI metadata/description](https://pypi.org/pypi/mcplint-cli/json), [repository](https://github.com/akashkokare2910/mcplint) | PyPI 0.2.0 describes 15 deterministic description/schema rules, ambiguity analysis, optional model-backed benchmarks, contract validation, generated adversarial benchmarks, mutations and confusion analysis. It already uses the name “ContractLab” for a feature. Core linting needs no model key. | No-key operation and contracts are not unique. Position this independent project carefully and investigate naming confusion before public distribution.                                                                                                                                                |

Phase 0 proves only local discovery and one fixed value check using SDK v2, plus
an intentionally wrong expectation with a nonzero exit. No reusable behavior suite,
schema diff, comparative benchmark, public adoption or measured advantage is
implemented. The build plan's initial competitive framing is a proposal; the
observations above supersede any assumption that competing tools lack behavior
tests. Update this comparison with executable examples after the relevant phases.
