# Phase 6 beta release candidate

**NO-GO for public publication.** This is release preparation, not a published beta,
production-readiness statement, maintainer approval or independent human validation.
Version stays `0.1.0-beta.1`; `private: true` stays enabled. No tag/release is created.

## Evidence and reproducibility

```sh
npm ci
npm run build
npm run release:notices
npm run release:audit -- /tmp/mcpcl-release-audit
npm run release:candidate -- /tmp/mcpcl-beta-candidate
npm run release:verify -- /tmp/mcpcl-beta-candidate/mcp-contractlab-0.1.0-beta.1.tgz /tmp/mcpcl-beta-candidate/consumer
```

Use fresh directories outside the checkout. Candidate preparation explicitly builds,
checks the manifest/bin/shebang and allowlist, records a dry-run inventory, packs
twice and requires identical SHA-256 archives. It preserves `private: true`, never
calls publication APIs, and caps compressed/unpacked size at 2/8 MiB. These are
candidate-review budgets, separate from the existing 4 MiB report budget.

The tarball, `candidate.json`, `pack-dry-run.json` and `SHA256SUMS` are local/CI
artifacts, not checked into Git. The SHA belongs to that exact archive and source
state; do not put a self-referential tarball hash inside packaged documentation.
CI uploads allowlisted evidence for each runtime, with limited retention. Download
an artifact from its specific successful Actions run; verify `SHA256SUMS` before
installing. CI artifacts are not npm provenance attestations or signed releases.

`release:verify` uses independent temporary consumers, a private cache and a
captured consumer lockfile. It first installs with lifecycle scripts disabled,
inspects the resolved graph for install hooks and runs a runtime vulnerability audit
of that actual consumer lock (not only the source lock), deletes node_modules, then performs
an **offline default-lifecycle `npm ci`**. Unexpected hooks fail verification.
Consumer locks are necessary: our source lock pins development, but npm tarball
consumers resolve transitive ranges independently; root pins do not reserve every
transitive version forever. No registry availability is required for the second
install after its cache is populated.

The installed binary, not working-tree source, must pass help/version/Chinese,
inspect, pass/fail/blocked runs, invalid config, JSON/JUnit locale parity, snapshot
stability, unchanged/removed-tool diffs and HTML generation. Runtime versions,
archive/consumer-lock hashes and actual dependency graphs are retained. Linux Node
22/24 CI is authoritative for those combinations; this is not Windows/macOS proof.
A separate browser check opens HTML generated by an installed tarball offline.

## Fresh audit observations

Observed 2026-10-25 against the public npm registry: `mcp-contractlab` returned 404;
no public record or maintainers were observed. **This does not reserve the name,
prove ownership, establish trademark clearance or guarantee npm will accept it.**
No npm identity or publishing rights were verified; no credentials were requested.
Prior naming overlap with MCPLint's “ContractLab” feature remains a review item.
The audit script rechecks current public metadata and records uncertainty explicitly.

At this audit, root runtime and full development `npm audit` reported zero findings.
That is time-scoped registry evidence, not a safety guarantee. Rerun immediately
before any approved release; unavailable audit data is unknown, not zero. Audit
collection can finish successfully while its release decision remains NO-GO.

The [runtime inventory](runtime-inventory.json) contains 23 resolved runtime
packages and no preinstall/install/postinstall hooks. [Third-party notices](../../THIRD_PARTY_NOTICES.md)
retain original license texts and hashes. SDK declarations say Apache-2.0, but the
actual license describes an Apache/MIT transition and documentation licensing.
A maintainer must review obligations; generated inventories are not legal advice.
Test-only upstream servers are excluded from the distribution and have separate
[provenance and license caveats](independent-validation.md).

## Release gates

| Gate                                                  | Assessment                                                                                 |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Source checks and packaged consumers                  | Verified by the linked exact-head PR CI, not by a future plan                              |
| Byte-identical repeated archive on one source/runtime | Required by candidate script; cross-platform reproducibility is not claimed                |
| Registry name/owner/publisher identity                | **Unverified**; 404 is not ownership                                                       |
| Naming confusion / transition license review          | **Open maintainer gate**                                                                   |
| Independent human clean installation and feedback     | **Not collected**; automated temporary consumers are not independent humans                |
| Live public-host HTTPS/TLS MCP interoperability       | **Unverified**; no owner-controlled disposable public host/endpoint authorization supplied |
| Trusted publisher/provenance/release approval         | **Proposed only**, not configured or granted                                               |

The final decision remains **NO-GO** until every open gate is explicitly resolved.
No public third-party MCP endpoint was probed. In-memory/injected HTTP tests and
local stdio validation cannot prove public TLS, certificate-chain, DNS or proxy
interoperability. See [checklist](checklist.md) and [supply-chain proposal](supply-chain.md).
